# 数仓治理与运维平台

面向数据仓库团队的治理与运维一体化平台。覆盖表生命周期管理、存储成本优化、数据热度分析、任务依赖编排、SLA告警、资源弹性调度与数仓健康度评估的完整治理链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 冷数据成本试算

在「存储成本优化」模块内提供可执行的冷数据成本试算视图（前端入口：`/cost/trial`，或从成本报告列表页跳转）。

- **候选演算**：按分析范围关联热度记录（含分区访问明细）与分层存储策略，产出三类候选——
  迁移候选（热度/容量条件一致）、冲突裁决（两条件冲突时按管理优先级判定并记录依据）、
  热点保留（热点分区不得仅因总量大被判为冷数据）。候选表按预计节省降序，列出建议目标层、
  预计释放容量、迁移成本、回本周期与风险明细。
- **版本确认**：试算版本确认动作在锁内做检查-置位，两个操作人员并行确认同一版本时只放行一次，
  重复确认不会生成第二份方案。
- **演算快照**：确认时把当时口径深拷贝进快照（`SNAP-xxxx`），成本报告、分层定义（成本报告引用）、
  热度记录（试算引用）统一引用该快照；热度页可按采样批次追溯引用关系。
- **口径隔离**：热度/分层口径调整会生成新口径版本（`CLB-2026-11-A` → `B`…），
  既有报告按原采样口径保留，新试算按新口径重新核算，结果同步到分层定义清单。

主要接口：`GET/POST /api/cost/caliber`、`GET/POST /api/cost/trials`、`POST /api/cost/trials/{id}/confirm`、
`GET /api/cost/snapshots`、`GET /api/cost/scopes`、`GET /api/heatmap/batches`。

试算引擎的业务规则测试：`cd backend && .venv/bin/python -m tests.test_cost_trial`

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
